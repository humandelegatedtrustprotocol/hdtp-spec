# The HDTP name guard's list: what no tracked file of an HDTP or BatonDeck repository may carry, in
# its path or in its text. One list, byte-identical in every repository whose gate runs the guard;
# this copy, in hdtp-spec, is the canonical one, and each other copy is compared with it whenever
# hdtp-spec is checked out beside that repository.
#
# The guard reads the TREE (`git ls-files`), never history. It skips binary files (any NUL byte),
# built and vendored output (dist/, node_modules/, target/) and go.sum, whose lines are hashes.
#
# Lines, after comments (#) and blank lines:
#
#   name <word>                       forbidden, case-insensitive, wherever it occurs: inside a
#                                     longer word, after a digit, an underscore or an escape
#   except-after <prefix>             ...unless the letters right before it are <prefix>,
#                                     case-insensitive. This is how English words pass
#   retired <regular expression>      forbidden, case-sensitive: a name of a behaviour HDTP does not
#                                     have. Written to run unchanged in JavaScript and in Go (RE2)
#   allow <repo> <path> <text>        in repository <repo> (its origin remote's name), file <path>,
#                                     a forbidden name inside the exact <text> is allowed. An entry
#                                     whose text is not in its file fails as stale, in that
#                                     repository's gate and in no other; an occurrence inside a
#                                     longer entry's text is the longer entry's
#   once <repo> <path> <text>         as allow, and <text> must occur exactly once in that file and
#                                     in no other file of the repository
#
# The guard fails when it reads fewer than one name or ten retired names: then the reader is broken,
# not the tree.

name pact
except-after im
except-after com
