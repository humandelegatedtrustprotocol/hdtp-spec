# pact-protocol.com: the specification, live — plan (draft for owner approval, 2026-09-30)

Owner: publish the whole PACT specification on pact-protocol.com "like google have for A2A", not only
in the whitepaper; two public major versions, no more than 2.0 ("version 1 … e2e closed platform,
version 2 … more democratised"); a polished public timeline instead of the development churn;
diagrams wherever required, visual learning first.
Research: scratchpad protocol-site-research.md (file:line and commit references for every fact below).

## The public story (true of the texts)

| Public | Internal texts | Shown publicly as | One line |
|---|---|---|---|
| **PACT 1** | 1.0.0, 1.2.0 (tag v1.2.0) | "superseded" (no dates) | Direct, end-to-end encrypted agent-to-agent messaging; your identity was the key of the machine that ran your agent; whoever hosted you held it; a relay carried your mail when you were offline. |
| **PACT 2** | 2.0.0 … 2.2.4 | "current, revised <date of the pinned text>" | The identity is yours, not your host's: you are the certificate authority (often from a passkey); any host serves you under a leaf you sign; move hosts without losing a contact; no relay in the middle; the sender hidden from carriers. |

- These are the protocol's own majors (the only version on the wire: `X-PACT-VERSION:2`, envelope
  `v: 2`, `pact_export: 2`), so the labels are not a relabelling.
- "Democratised" is true of PACT 2. "Closed platform" is NOT true of PACT 1: 1.2.0 describes an open,
  self-hostable, already end-to-end protocol. What separated them is who held the identity (host vs
  person) and the relay. The site uses the wording above unless the owner supplies other wording the
  1.2.0 text supports (decision D1).
- No release ranges are shown: both majors fell within about five weeks, and dates would say so. Nothing
  invented, dates simply left out; no revision history page.
- The intermediate drafts (1.1.0-draft, 2.0.0-draft, 2.1.x, 2.2.0–2.2.3) are not published as pages.
  PACT 2's current text carries "PACT 2 · revised 2026-09-28"; its internal id (2.2.4) appears only in
  small print (option A: no wire, library or Wasm-pin change).

## Hiding the churn inside the text (decision D4)

SPEC.md itself carries the development history: a ~2,000-character revision narrative in its header
and about 20 in-body version references ("added in 1.1", "from 2.0" …). Rendering it verbatim would
publish exactly what the owner wants off the public page. Two ways:
- **Generator transform:** the site omits the header narrative; a named, tested transform (not byte
  equality). Cheap, but the ~20 in-body references still show.
- **Edit SPEC.md (option B):** move the narrative to a CHANGES file and rewrite the in-body references
  as timeless prose. Complete; any MUST sentence touched changes pact-identity's `musts.json` hashes,
  so both ports re-verify those MUSTs in the same change. The version token stays, so no Wasm re-pin.

## Site (A2A's shape, sized to PACT)

- `/` — protocol home, CTA "Read the specification".
- `/learn/` — 10 visual topic pages, each with at least one diagram: What is PACT · PACT, MCP and A2A ·
  Identity (root, leaf, passkey) · Contacts and invites · Permissions and tiers · Messages and threads ·
  Hosting and moving · Sealed envelopes · Certificates and renewal · Security model and trade-offs.
- `/spec/` — PACT 2, the full normative text: one long page with a sticky table of contents and stable
  §-anchors (A2A's choice; Ctrl-F and citation), plus a MUST index.
- `/spec/whats-new/` — "What's new in PACT 2": added and removed, as features (research §6a).
- `/spec/pact-1/` — PACT 1 text, bannered "superseded; refused by every PACT 2 implementation"
  (or only described on What's new — decision D2).
- `/spec/vectors/` — Appendix B test vectors, download and rendered.
- `/whitepaper/` — per decision D3. `/privacy/` updated to match whatever the site collects.

## Diagrams

The site's CSP (`style-src 'self'`) and the kit's no-`style=` rule forbid in-browser Mermaid. Every
diagram is pre-rendered at build time to class-styled SVG, themed by the kit (light and dark). SPEC.md's
9 Mermaid diagrams render from source; topic-page diagrams are drawn for the page; where one mirrors a
spec diagram, a test holds its labels to the Mermaid source.

## Build (each item: own branch/worktree, its repo's gates, pushed; deploys are the owner's)

1. **pact-web-kit**: a docs layout (sidebar, sticky TOC, anchors, diagram classes, dark mode) → release.
2. **pact-protocol**: a generator beside `build-whitepaper.mjs` that renders a given SPEC commit to
   HTML fragments + SVGs. PACT 1 is rendered from `git show d130444:SPEC.md` at build time, never
   committed as markdown (its 29 marker lines would fail `check-no-1x`). Tag the pinned 2.x release.
   Fix pact-protocol CLAUDE.md's two stale claims (CI publishing; "-draft" version line).
3. **pact-protocol-site**: vendor the fragments under `public/spec/` with a `spec.lock` (commit +
   version); `test/spec.test.mjs` regenerates from `../pact-protocol` at the locked commit and demands
   equality; learn pages hand-written, every factual sentence checked against its §; site.json verify
   list gains every new path; `make check`, then the owner's `make deploy` + `make verify`.
4. Sequence: kit → generator → spec pages → What's new → learn pages → home/whitepaper → deploy.

## Decisions (owner, 2026-09-30)

- **D1** PACT 1 is described truthfully: open, self-hostable, already end-to-end encrypted; what
  changed in PACT 2 is who holds the identity (the person, not the host) and the relay (gone). The
  polish is in how releases and progression are presented, never in what a version was.
- **D2** PACT 1's full text (1.2.0) is published at /spec/pact-1/, bannered superseded and refused by
  every PACT 2 implementation.
- **D3** The whitepaper PDF stays registration-gated beside the open HTML spec.
- **D4** SPEC.md is edited: the header's revision narrative moves to CHANGES.md (internal), the in-body
  version references become timeless prose; the version token stays; any MUST sentence touched is
  re-verified in both pact-identity ports in the same change.
- Defaults taken: option A labels (no library or pin change); one long spec page; vectors and MUST
  index public; the pinned 2.x text tagged; no dates on the public timeline; no revision-history page.
